# 03. Security & Access Document: Servant AI

**Version:** MVP 0.1  |  Security is the product's core claim. Every statement here should be true of the running code; anything not yet implemented is marked **[TODO]**.

## 1. Security goals
1. **No data leaves the machine** (confidentiality of documents, prompts, outputs).
2. **Prove it**, not just claim it: logs, monitor, unplug test.
3. **Contain the agent:** the model can only use a small, explicit set of tools with bounded power.
4. **Least exposure:** the UI is reachable only by the intended users.

## 2. Assets
Uploaded documents and the knowledge base; user prompts and chat history; generated deliverables; model server and weights; logs.

## 3. Threat model
| # | Threat | Impact | Mitigation |
|---|---|---|---|
| T1 | App or a library calls the internet (telemetry, update checks, CDN assets) | Data exfiltration | Socket guard; disable telemetry; no CDN assets; container without egress; host firewall |
| T2 | Model-written code exfiltrates data or opens a network connection | Exfiltration | Run in Docker `--network none` **[TODO]**; MVP demo with network off; timeouts |
| T3 | Model-written code damages files | Data loss | Run in throwaway workspace directory; Docker with read-only mounts **[TODO]** |
| T4 | Prompt injection inside an uploaded document ("ignore rules, run this code") | Unauthorized tool use | KB mode has **no** `run_python`; documents are wrapped as CONTEXT/data; tool allow-list per mode; step trace visible |
| T5 | Another machine on the LAN opens the UI | Unauthorized access | Bind to `127.0.0.1` by default; login **[TODO]** for shared deployments |
| T6 | Path traversal via generated filenames | Overwrite arbitrary files | `make_docx` keeps only `Path(filename).name` and writes to `workspace/out/` |
| T7 | Tampered model or dependency supply chain | Malicious behavior | Pin versions, verify checksums of weights, install from an internal mirror **[TODO]** |
| T8 | Sensitive data left in logs or history | Leakage on shared machines | Logs store destinations, not content; history in memory; clear-KB button; encrypt-at-rest **[TODO]** |

## 4. Sovereignty controls (layered)
| Layer | Control | Status |
|---|---|---|
| L1 In-process | `socket.socket.connect` wrapper allows only loopback/private IPs, logs every attempt (ALLOWED/BLOCKED), sidebar counter | Implemented in `app.py` |
| L2 Config | Telemetry off (`--browser.gatherUsageStats=false`), `HF_HUB_OFFLINE=1`, no hosted-API keys, no CDN fonts/scripts in UI | Partly implemented |
| L3 Container | Compose network pinned to an explicit subnet; `no-new-privileges`, all capabilities dropped, PID and memory caps, non-root | Implemented for the app container; the model server stays on the host, so the bridge is not `internal: true` |
| L4 Host firewall | nftables DROP + LOG for container egress, generated by `app.host_firewall_rules()` and applied by `deploy/firewall.sh` | Implemented and unit tested; runtime `apply` needs a Linux host, not verified on Windows |
| L5 Physical | Unplug/disable network and run the whole demo | Demo procedure |
| L6 Independent evidence | `tcpdump -i any not host 127.0.0.1 and not net 10.0.0.0/8` shows no packets; `ss -tnp` shows only local sockets | Demo procedure |

**Honest limits (state these to judges):** L1 protects only the Python process that hosts the app. Code run with `run_python` executes in a subprocess that L1 does not cover, so the sandbox must be network-isolated (L3/L4/L5). The claim is "no external calls in the demo, proven by independent monitoring", and L4 now adds a host-level default-deny for container egress, but the nftables rules have only been unit tested on Windows: they have never been loaded on a Linux host, so say "generated and unit tested, apply it on your deployment host and run `status` to confirm the drop counters" rather than claiming it is proven in your run.

## 5. Agent and tool safety
- **Allow-list per mode:** General = `run_python`, `make_docx`; KB = `search_kb`, `make_docx`.
- **Bounded loop:** max 6 steps; each tool call and result is shown in the UI.
- **`run_python`:** 20 s timeout; output truncated; runs with cwd `workspace/`. Production: Docker (`--network none --read-only --memory 512m --cpus 1 --pids-limit 100`, non-root user, no host mounts except a scratch dir).
- **No shell tool** in MVP. No arbitrary file read/write tool; only `make_docx` writes, only into `workspace/out/`.
- **Document content is data:** KB prompt states that instructions found inside context must be ignored **[TODO: add this line to the KB prompt]**.
- **Cited answers:** KB mode citations let users verify claims against sources.

## 6. Access control
### MVP (single user, single machine)
- UI served on localhost. Set compose port mapping to `127.0.0.1:8501:8501`.
- No accounts. Physical/OS-level access is the access boundary.

### Full product roles (post-MVP)
| Role | Capabilities |
|---|---|
| Admin | Configure endpoint and allowed models, view audit log, manage users, manage all KBs |
| Contributor | Upload to permitted knowledge bases, use both modes |
| Viewer | KB mode only on permitted knowledge bases, no code execution |
| Auditor | Read-only audit log and network log |

Additional planned controls: local username/password (bcrypt) or LDAP/AD, per-department knowledge bases with document-level ACLs enforced **before** retrieval, session timeout, optional TLS on LAN, admin toggle to disable General-mode code execution.

- All data stored under `workspace/` (Docker volume). Nothing is sent anywhere.
- Deleting a document removes its chunks and vectors **[TODO]**; "Clear KB" deletes `kb.pkl`.

- Model weights are supplied by the user and are never downloaded by the app at runtime.

## 9. Secure deployment checklist
- [ ] Pre-download weights, wheels and Docker images on a connected machine; move offline.
- [x] Disable telemetry in Streamlit and any library; set `HF_HUB_OFFLINE=1`.
- [x] Bind UI to localhost (or LAN with login).
- [x] Pin the container subnet and add host firewall DROP+LOG (`deploy/firewall.sh apply`).
- [ ] Run `run_python` only in the network-less Docker sandbox (available via `SERVANT_RUNNER_IMAGE`, off by default).
- [ ] Verify with tcpdump/`ss` and an unplug test; save the evidence.
- [ ] Pin dependency versions; record model checksums.

## 10. Sovereignty test plan (for the demo)
1. Start monitoring (`tcpdump` filter above and the in-app monitor).
2. Run KB question, General code task, screenshot task, and `.docx` generation.
3. Show zero external packets and "0 blocked" in the app.
4. **Negative test:** ask General mode to run `requests.get("https://example.com")`. With network off or Docker `--network none` it fails; show the failure and the log.
5. Repeat the run with Wi-Fi/Ethernet disabled.
